# サーバーを決まった番地（ポート）で起動する

このアプリは、次の番地で動かすと決めてある（`docs/技術スタック.md` 2.3）。
画面とサーバーは、この番地でつながる作りになっている。別の番地で起動すると、アプリはうまく動かない。

| 動かすもの | 番地 | 起動する場所 | 起動のコマンド |
| --- | --- | --- | --- |
| データベース（PostgreSQL） | 5432 | リポジトリの一番上 | `docker compose up -d` |
| サーバー（Spring Boot） | 8080 | `backend` | `.\gradlew.bat bootRun` |
| 画面（Vite） | 5173 | `frontend` | `npm run dev` |

## 必ず守ること

- 上の表の番地だけで起動する。
- 番地がふさがっていたら、**ふさいでいるプロセスを止めてから**、同じ番地で起動する。
- 別の番地では、一時的にでも起動しない。次のようなことは、してはいけない。
  - `npm run dev -- --port 5174`、`vite --port ...` のように、番地を指定して起動する
  - `--server.port=...`、`-Dserver.port=...`、`SERVER_PORT`、`PORT` などで、サーバーの番地を変える
  - `vite.config.ts`、`application.properties`、`compose.yaml` の番地を書き換える
  - `vite.config.ts` の `strictPort: true` を外す（これがあると、Vite は番地がふさがっているときに、別の番地へ逃げずに止まる）
- ふさいでいるプロセスを止められないときも、別の番地には逃げない。起動をやめて、何が番地をふさいでいるかをユーザーに伝える。

## 手順

データベース、サーバー、画面の順に起動する。起動するものごとに、次の 1〜4 を行う。

### 1. 番地がふさがっているかを確かめる

PowerShell で、番地を待ち受けているプロセスを調べる（例は 8080。番地は読みかえる）。

```powershell
Get-NetTCPConnection -LocalPort 8080 -State Listen -ErrorAction SilentlyContinue |
  Select-Object -ExpandProperty OwningProcess -Unique |
  ForEach-Object { Get-Process -Id $_ | Select-Object Id, ProcessName, Path }
```

何も出なければ、番地は空いている。3 へ進む。

### 2. ふさいでいるプロセスを止める

1 で出たプロセスを止める。

```powershell
Stop-Process -Id <プロセスの番号> -Force
```

止めたあと、もう一度 1 を行い、番地が空いたことを確かめる。

データベースの番地（5432）だけは、次のように扱う。

- `docker ps` で、このアプリのコンテナ `taskmanagement-db` が動いていれば、データベースはもう正しい番地で起動している。止めずに、そのまま使う。
- それ以外のもの（別のコンテナや、パソコンに入っている別の PostgreSQL）がふさいでいるときは、それを止める。コンテナなら `docker stop <コンテナの名前>` を使う。

### 3. 決まった番地で起動する

上の表のコマンドで起動する。番地を指定するオプションは付けない。
サーバーと画面は、動かし続けるものなので、バックグラウンドで起動する。

### 4. 決まった番地で動いていることを確かめる

- サーバー：`http://127.0.0.1:8080/api/board` が返事をする
- 画面：`http://localhost:5173` が返事をする。`http://localhost:5173/api/board` も返事をする（Vite がサーバーへ取り次いでいる）
- 起動の記録に、表とちがう番地が出ていないことを確かめる

## ユーザーに伝えること

- どの番地で、何を起動したか
- プロセスを止めたときは、止めたプロセスの名前と番号、ふさいでいた番地
- 止められなかったときは、何が番地をふさいでいるかと、起動していないこと
