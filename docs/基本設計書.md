## 0. この文書について

要件定義書で決めた「何を作るか」をもとに、「どう作るか」を決める。図は Mermaid 記法で書く。

画面とデータの設計は、次の文書に分けて書く。

| 文書 | 内容 |
| --- | --- |
| [画面設計](画面設計.md) | 画面ごとの項目、表示のルール、画面の移り方、入力のチェック |
| [データ設計](データ設計.md) | データの形、ER図、テーブルの定義、並び順の持ち方 |

この文書では、使うデータベースやサーバーの具体的な製品は決めない。それらは、この文書のあとで決め、[技術スタック](技術スタック.md)に書く。

## 1. システム構成

### 1.1 第1段階

画面だけで動き、データはブラウザの `localStorage` に保存する。

```mermaid
flowchart LR
    User(["利用者"])
    subgraph PC["自分のパソコン"]
        subgraph Browser["ブラウザ"]
            UI["画面"]
            Repo["保存係<br>localStorage 用"]
            LS[("localStorage")]
        end
    end
    User -- 操作 --> UI
    UI -- 読み込み・保存の依頼 --> Repo
    Repo -- 読み書き --> LS
```

### 1.2 第2段階

画面、サーバー、データベースの3つに分かれる。3つとも自分のパソコンの上で動く。

```mermaid
flowchart LR
    User(["利用者"])
    subgraph PC["自分のパソコン"]
        subgraph Browser["ブラウザ"]
            UI["画面"]
            Repo["保存係<br>サーバー用"]
        end
        Server["サーバー"]
        DB[("データベース")]
        Log["エラーの記録"]
    end
    User -- 操作 --> UI
    UI -- 読み込み・保存の依頼 --> Repo
    Repo -- HTTP で通信 --> Server
    Server -- SQL --> DB
    Server -- 書き込み --> Log
```

### 1.3 保存係で保存先を差し替える

画面は、データを保存するときに「保存係」に頼むだけにする。保存係は、保存先ごとに2つ作る。

- 第1段階：`localStorage` に保存する保存係
- 第2段階：サーバーに保存を頼む保存係

画面から見ると、どちらの保存係も同じ頼み方で使える。そのため、第2段階で保存係を入れ替えても、画面の部品は書き換えずに済む（[非機能要件](非機能要件.md) 7章）。

保存係が引き受ける仕事は次のとおり。

| 仕事 | 内容 |
| --- | --- |
| ボードを読み込む | ボード全体のデータを返す |
| カードを追加する | 指定したカラムの一番下に、カードを1枚加える |
| カードを更新する | カードの4項目を書き換える |
| カードを削除する | カードを1枚消す |
| カードを移動する | カードを、指定したカラムの指定した位置へ移す。同じカラムの中の並べ替えも含む |
| ボードを置き換える | バックアップの読み込みで、ボード全体を入れ替える |

## 2. データの流れ

### 2.1 全体

```mermaid
flowchart LR
    File[/"バックアップのファイル"/]
    subgraph Browser["ブラウザ"]
        UI["画面"]
        State["画面の中のデータ"]
        Repo["保存係"]
    end
    LS[("localStorage<br>第1段階")]
    Server["サーバー<br>第2段階"]
    DB[("データベース<br>第2段階")]

    UI -- 操作 --> State
    State -- 表示 --> UI
    State -- 保存の依頼 --> Repo
    Repo -- 読み込んだデータ --> State
    Repo <--> LS
    Repo <--> Server
    Server <--> DB
    State -- 書き出し --> File
    File -- 読み込み --> State
```

### 2.2 アプリを開いたとき

第1段階

```mermaid
sequenceDiagram
    actor U as 利用者
    participant UI as 画面
    participant R as 保存係
    participant LS as localStorage

    U->>UI: アプリを開く
    UI->>R: ボードを読み込む
    R->>LS: 保存したデータを読む
    alt データがある
        LS-->>R: ボードのデータ
        R->>R: 正しい形か確かめる
        R-->>UI: ボードのデータ
        UI-->>U: ボードを表示する
    else データがない
        LS-->>R: なし
        R-->>UI: 3つの空のカラム
        UI-->>U: 空のボードを表示する
    else データが壊れている
        R-->>UI: 読めないことを知らせる
        UI-->>U: お知らせ欄にエラーを表示する
    end
```

壊れたデータは消さずに残す（[非機能要件](非機能要件.md) 3章）。

第2段階

```mermaid
sequenceDiagram
    actor U as 利用者
    participant UI as 画面
    participant R as 保存係
    participant S as サーバー
    participant DB as データベース

    U->>UI: アプリを開く
    UI-->>U: 読み込み中と表示する
    UI->>R: ボードを読み込む
    R->>S: ボードをください
    alt サーバーが動いている
        S->>DB: カラムとカードを読み出す
        DB-->>S: カラムとカードの行
        S->>S: 画面用の形に組み立てる
        S-->>R: ボードのデータ
        R-->>UI: ボードのデータ
        UI-->>U: ボードを表示する
    else サーバーにつながらない
        R-->>UI: つながらないことを知らせる
        UI-->>U: お知らせ欄と再読み込みボタンを表示する
    end
```

### 2.3 カードを追加、編集、削除したとき

画面のデータを先に書き換えて表示し、そのあとで保存する。保存に失敗したときは、画面のデータを操作の前に戻す。

こうすると、サーバーの返事を待たずに結果が画面に出るので、操作が速く感じられる（[非機能要件](非機能要件.md) 2章）。特にドラッグ＆ドロップでは、返事を待つ間にカードが元の位置へ一瞬戻ってしまうことを防げる。

次の図は、第2段階でカードを追加するときの流れ。編集と削除も同じ流れになる。

```mermaid
sequenceDiagram
    actor U as 利用者
    participant UI as 画面
    participant R as 保存係
    participant S as サーバー
    participant DB as データベース

    U->>UI: 入力して「追加」を押す
    UI->>UI: 入力をチェックする
    alt 入力に問題がある
        UI-->>U: 入力欄の下にメッセージを出す
    else 問題がない
        UI->>UI: カードの id を作る
        UI->>UI: 画面のデータにカードを加える
        UI-->>U: カードを表示する
        UI->>R: カードを追加する
        R->>S: カードを追加してください
        S->>S: 入力をチェックする
        S->>DB: カードを1行加える
        alt 成功
            DB-->>S: 完了
            S-->>R: 成功
            R-->>UI: 成功
        else 失敗
            S-->>R: 失敗
            R-->>UI: 失敗
            UI->>UI: 画面のデータを追加の前に戻す
            UI-->>U: お知らせ欄にエラーを表示する
        end
    end
```

第1段階では、サーバーとデータベースの代わりに、保存係がボード全体を `localStorage` へ書き込む。

### 2.4 カードを移動、並べ替えたとき（第2段階）

```mermaid
sequenceDiagram
    actor U as 利用者
    participant UI as 画面
    participant R as 保存係
    participant S as サーバー
    participant DB as データベース

    U->>UI: カードをドロップする
    UI->>UI: 画面のデータの並び順を変える
    UI-->>U: 新しい並び順で表示する
    UI->>R: カードを移動する（移動先のカラムと位置）
    R->>S: カードを移動してください
    S->>DB: トランザクションを始める
    S->>DB: 移動元のカラムの番号を振り直す
    S->>DB: 移動先のカラムの番号を振り直す
    alt すべて成功
        S->>DB: 確定する
        S-->>R: 成功
        R-->>UI: 成功
    else 途中で失敗
        S->>DB: すべて取り消す
        S-->>R: 失敗
        R-->>UI: 失敗
        UI->>UI: 並び順を移動の前に戻す
        UI-->>U: お知らせ欄にエラーを表示する
    end
```

番号の振り直し方は、[データ設計](データ設計.md) 3.4 に書く。

### 2.5 バックアップを書き出したとき

画面の中のデータを、そのままファイルにする。第2段階でも、サーバーには問い合わせない。

```mermaid
sequenceDiagram
    actor U as 利用者
    participant UI as 画面

    U->>UI: 「書き出し」を押す
    UI->>UI: 画面のデータに書き出した日時を加える
    UI-->>U: JSON ファイルをダウンロードさせる
```

### 2.6 バックアップを読み込んだとき

```mermaid
sequenceDiagram
    actor U as 利用者
    participant UI as 画面
    participant R as 保存係

    U->>UI: 「読み込み」を押してファイルを選ぶ
    UI->>UI: ファイルの中身を確かめる
    alt 正しくない
        UI-->>U: このファイルは読み込めませんと表示する
    else 正しい
        UI-->>U: S-5 読み込み確認ダイアログを開く
        alt 置き換える
            U->>UI: 「置き換える」を押す
            UI->>R: ボードを置き換える
            R-->>UI: 結果
            UI-->>U: 新しいボードを表示する
        else キャンセル
            U->>UI: 「キャンセル」を押す
            UI-->>U: 何も変えずに閉じる
        end
    end
```

第2段階では、サーバーが「今のカードを全部消して、ファイルのカードを入れる」を1つのトランザクションで行う。途中で失敗したときは、読み込む前のボードのまま残る。

ファイルの中身は、次をすべて満たすときに正しいとする。

- JSON として読める
- `version` が `1`
- `columns` に `todo`、`doing`、`done` の3つがそろっている
- すべてのカードが、[画面設計](画面設計.md) 10章の入力のチェックを満たす
- すべてのカードが、どれか1つのカラムに1回だけ入っている
- `columns` に、`cards` にない id が入っていない

## 3. サーバーの窓口（第2段階）

画面の保存係がサーバーに頼むときの窓口（API）を、次のように分ける。送るデータと返すデータの細かい形は、詳細設計で決める。

表の中の「ボードの形」は、[データ設計](データ設計.md) 2.2 の形を指す。

| 保存係の仕事 | 方法 | 窓口 | 内容 |
| --- | --- | --- | --- |
| ボードを読み込む | GET | `/api/board` | ボード全体をボードの形で返す |
| カードを追加する | POST | `/api/cards` | カードと、追加するカラムを送る |
| カードを更新する | PATCH | `/api/cards/{id}` | 変えた項目を送る |
| カードを削除する | DELETE | `/api/cards/{id}` | |
| カードを移動する | PUT | `/api/cards/{id}/position` | 移動先のカラムと、上から何番目かを送る |
| ボードを置き換える | PUT | `/api/board` | ボードの形のボード全体を送る |

- サーバーは、同じパソコンからの接続だけを受け付ける（[非機能要件](非機能要件.md) 6章）
- サーバーで起きたエラーは、日時と内容をエラーの記録に残す（[非機能要件](非機能要件.md) 4章）
